الجمهور المستهدف

«كل المشتركين» يستخدم الشريحة الافتراضية Subscribed Users. الاستهداف عبر Tags/اللغة/الدولة يستعمل filters الرسمية. لا يمكن خلط filters مع شرائح أو aliases في طلب واحد.

الجدولة والتوقيت

الإرسال مرة واحدة فقط. الحملات المتكررة غير مدعومة عبر API (استخدم Journeys في لوحة OneSignal أو مجدولًا خارجيًا). الجدولة تتم على خوادم OneSignal، فهي تستمر بعد إغلاق المتصفح.

كل عملية إرسال تطلب تأكيدًا، وتحمل idempotency_key لمنع التكرار عند إعادة المحاولة.

    خيارات تحسين وقت الإرسال

    هذه الخيارات تمرّ كما هي إلى OneSignal عبر الحقل delayed_option. هذا القسم لا يطبّق أي ذكاء اصطناعي محلي، والخدمة وحدها تقرر الوقت، وقد تُرفض بعض الخيارات حسب الخطة (وتُعرض رسالة الرفض كما هي).

    نتائج المقارنة: أرسل نسختين (مع وبدون الخيار) من تبويب A/B، ثم قارن معدل النقر من تبويب التحليلات. لا تُعرض أرقام قبل توفر بيانات فعلية.

    إعدادات الاتصال

    حالة الاتصال: لم تُفحص · آخر تحقق: —

    لا تُحفظ المفاتيح في هذه الإعدادات إطلاقًا. للتشغيل الفوري استخدم «الوضع المباشر المؤقت» أدناه (ذاكرة فقط)، وللتشغيل الآمن الدائم استخدم Supabase.

    الوضع المباشر المؤقت للتشغيل الفوري — الأمان لاحقًا

    يعمل بدون Supabase: الصق المفاتيح هنا فتبقى في ذاكرة هذه الصفحة فقط (لا تُحفظ في الملفات ولا في المتصفح، وتزول عند إغلاق التبويب أو الخروج)، ويتصل المتصفح بـ OneSignal وGitHub مباشرة. لهذا الوضع حدود:

    • قد يمنع OneSignal الطلبات المباشرة من المتصفح (CORS)؛ عندها تظهر رسالة واضحة ولا يُعلن أي نجاح، والحل النهائي هو دالة Supabase.
    • المفتاح يظهر لأي أداة مطوّر على جهازك، فاستخدمه من جهاز موثوق فقط، ولا تُبقِ التبويب مفتوحًا.
    • سجل الخادم (/audit) غير متاح في هذا الوضع.

    الوسيط: Supabase Edge Function (موصى به)

    عند ملء عنوان Supabase يتحول الدخول إلى Supabase Auth (بريد + كلمة مرور)، وتُرسل كل الطلبات إلى /functions/v1/osl-admin بـ Authorization: Bearer <access_token>. الدالة تتحقق من الـ JWT وتطابق البريد مع ADMIN_EMAILS، ثم تستخدم الأسرار من supabase secrets. الـ token يُحفظ في sessionStorage فقط (يزول بإغلاق التبويب). نفس مسارات العقد أدناه تنطبق، لكن بلا /auth/login و/auth/logout.

    العقد العام (Contract)

    كل الطلبات تُرسل بـ credentials: include وبيانات JSON. يجب أن يتحقق الوسيط من جلسة المسؤول (كوكي HttpOnly + Secure + SameSite) قبل كل عملية، وأن يضبط CORS لأصل هذه الصفحة فقط، ويضيف ترويسة Authorization: Key … من متغير بيئة.

    POST /auth/login          {username,password} → Set-Cookie (HttpOnly; Secure; SameSite=Strict)
GET  /auth/session        → {user}
POST /auth/logout
GET  /health              → {ok:true}
ANY  /onesignal/*         → https://api.onesignal.com/* (قائمة بيضاء من المسارات)
     POST   /onesignal/notifications
     GET    /onesignal/notifications?app_id=&limit=50
     GET    /onesignal/notifications/{id}?app_id=
     DELETE /onesignal/notifications/{id}?app_id=
     GET    /onesignal/apps/{app_id}
     GET    /onesignal/templates?app_id=
     GET|POST|DELETE /onesignal/apps/{app_id}/segments
     GET|PATCH|DELETE /onesignal/apps/{app_id}/users/by/external_id/{id}
GET  /audit               → [{time,user,op,campaign,result,code}]
GET  /github/file?repo=&branch=&path=      → {sha,content(UTF-8),commit:{sha,message,date}}
PUT  /github/file         {repo,branch,path,content,sha,message} → {commit:{sha,url}}
GET  /github/commits?repo=&branch=&path=   → [{sha,message,date}]

    أخطاء 401/403/404/429/5xx تُعرض للمسؤول برسالة مفهومة. مهلة الطلب 15 ثانية.

    إعداد OneSignal وHTTPS

    1. أنشئ تطبيق Web Push بعنوان موقعك الفعلي (HTTPS).
    2. ضع App ID في index.html (المتغير APP_ID) وفي الإعدادات أعلاه.
    3. ارفع OneSignalSDKWorker.js إلى جذر الموقع (سطر importScripts الرسمي) — ملف مطلوب من المتصفح خارج الملفين.
    4. أنشئ REST API Key من إعدادات التطبيق وضعه كمتغير بيئة في الوسيط فقط.
